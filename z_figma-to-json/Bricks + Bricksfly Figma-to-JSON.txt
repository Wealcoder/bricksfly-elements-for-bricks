# Bricks + Bricksfly Figma-to-JSON POC

I want to build a proof-of-concept that converts a website design/screenshot into a Bricks Builder website.

The target workflow is:

Figma screenshot/design
→ AI analyzes the design
→ AI determines the required Bricks/Bricksfly elements and settings
→ AI generates Bricks JSON
→ I import the JSON into Bricks Builder
→ Bricks renders the website

The website must be built using the existing **Bricks native functionality + Bricksfly functionality** available in this repository.

Do NOT build an MCP server yet. This is only the first POC to prove that the screenshot/design can be converted into valid Bricks JSON.

---

# 1. CRITICAL RULE — USE EXISTING BRICKS + BRICKSFLY FUNCTIONALITY

This is the most important requirement.

The generated website must use existing:

1. Bricks native elements/features
2. Bricksfly elements/extensions

Do not create new functionality when an existing Bricks or Bricksfly feature can implement the design.

Use this decision order for every design feature:

```text
Figma/design feature
        ↓
Can Bricks native functionality implement it?
        ↓
      YES → use Bricks native
        ↓ NO
Can an existing Bricksfly element/extension implement it?
        ↓
      YES → use Bricksfly
        ↓ NO
Ask me whether custom JavaScript is acceptable
```

Do NOT automatically create a workaround.

---

# 2. DO NOT INVENT FUNCTIONALITY

Do NOT:

* create new Bricks elements
* create new Bricksfly elements
* create new Bricksfly extensions
* invent Bricks control names
* invent Bricksfly control names
* invent Bricks settings
* invent Bricksfly settings
* create custom JavaScript automatically
* create custom GSAP animations automatically
* recreate an existing Bricksfly animation using JavaScript
* recreate an existing Bricks native feature using JavaScript
* create custom HTML when an existing Bricks element can be used
* create custom CSS animations when Bricks/Bricksfly already provides the required functionality

The purpose of this POC is to prove that the existing **Bricks + Bricksfly ecosystem** can reproduce the design.

---

# 3. CUSTOM JAVASCRIPT RULE

There may be cases where the screenshot contains functionality that cannot be reproduced using existing Bricks or Bricksfly functionality.

In that situation:

DO NOT write custom JavaScript immediately.

Instead, stop and ask me something like:

> "This design feature cannot be implemented using the existing Bricks or Bricksfly functionality I found. Would you like me to create custom JavaScript for this feature?"

Only after I explicitly approve it should you create the custom JavaScript.

If custom JavaScript is approved:

1. Explain why Bricks/Bricksfly cannot implement the feature.
2. Explain what the custom JavaScript will do.
3. Provide the JavaScript separately.
4. Then include the required configuration/reference in the final Bricks JSON if applicable.

Do not silently introduce custom JavaScript into the generated website.

# 8. MAP DESIGN → BRICKS

For every part of the screenshot, determine the appropriate existing Bricks element.

For example:

```text
Design heading
→ Bricks Heading

Design paragraph
→ Bricks Basic Text

Design CTA
→ Bricks Button

Design image
→ Bricks Image

Design layout
→ Bricks Section + Container + Block/Div

Design sticky behavior
→ Bricks native sticky feature OR Bricksfly Pin Element
```

Use the most appropriate native Bricks element rather than creating custom HTML.

---

# 9. MAP DESIGN → BRICKSFLY

If a design feature can be implemented using Bricksfly, use the existing Bricksfly functionality.

Examples:

```text
Floating animation
→ Bricksfly Floating Elements

Pin/sticky/scroll-based behavior
→ Bricks native feature if sufficient
→ otherwise Bricksfly Pin Element

Smooth scrolling
→ Bricksfly ScrollSmoother
```

These are examples only.

Inspect the actual repository before deciding which feature to use.

---

# 10. DO NOT OVERUSE BRICKSFLY

Do not use a Bricksfly feature just because it exists.

If a feature can be implemented cleanly using Bricks native functionality, use Bricks native functionality.

For example:

```text
Simple heading
→ Bricks Heading
```

not a custom Bricksfly element.

The goal is:

```text
Bricks native where possible
Bricksfly where necessary/appropriate
Custom JS only after explicit approval
```
